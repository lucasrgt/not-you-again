# Production-scale benchmark development attempts

The final pass was not selected from repeated identical runs. Earlier results
were preserved because they changed the scar guidance and confirmation
protocol.

| Attempt | Scale phase | Semantic result | What it exposed |
| --- | --- | --- | --- |
| [1](../v1.0.4-production-scale-attempt-1/ATTEMPT.md) | Passed before interruption | Three completed runs and one interrupted run | A fast judge treated a valid CSS token reference as a recurrence because the lesson did not state the compliant representation |
| [2](../v1.0.4-production-scale-attempt-2/REPORT.md) | Passed | 3 of 4 runs passed | Confirmation bias allowed `useMemo`, the named remedy, to be confirmed as recurrence in one run |
| [3](../v1.0.4-production-scale-attempt-3/REPORT.md) | Reduced 48-scar smoke passed | 1 of 2 runs passed | An explicitly adversarial verifier overcorrected and rejected one valid `useMemo` recurrence |
| [Final](REPORT.md) | Passed | 4 of 4 runs passed | Balanced independent verification passed both models twice |

The final protocol asks the second judge to verify independently without
presuming that the proposal is correct or incorrect. A finding survives only
when its evidence contradicts a concrete lesson requirement. Shared APIs,
topics, or terminology are insufficient, while code implementing the named
remedy must be rejected.
